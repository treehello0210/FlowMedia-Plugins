# 网络代理监控 1.0.0

插件 ID：`network_proxy_monitor`。要求主程序已经支持 **SDK 2** 的 `proxy.monitor` 和 `proxy.control` 能力；Python 3.11，清单格式 1。SDK 1 主程序不能安装本版本。

本插件包只有 `manifest.json`、`plugin.py` 两个文件。公开的是 SDK 调用示例与元数据；不包含 FlowMedia 主程序、采集实现、用户配置或凭据。主程序源码不需要提交到本仓库。

## 安装与配置

先升级到支持 SDK 2 的 FlowMedia，再上传 ZIP 或从对应插件市场分支安装。安装默认停用。选择 Clash 或 v2rayA，填写**管理 API 地址**，不是 HTTP/SOCKS 代理转发端口。保存、测试连接后再启用。密码字段默认遮蔽，保存后保留内容，通过小眼睛查看。

- Clash：地址、API Key（对应控制器 secret）。
- v2rayA：地址、API Key（登录令牌），或用户名和密码。令牌优先；用户名密码只发送至用户配置的 v2rayA 登录接口。
- 请求超时：默认 5 秒，范围 1–10 秒。

Docker 内的 `127.0.0.1` 指向 FlowMedia 容器本身。请使用容器能够访问的控制器地址，并将管理接口的访问范围限定于实际需要的网络。

连接测试使用当前表单内容，不保存配置。监控与控制使用已保存配置。修改未保存时暂停监控操作，避免在旧服务上误操作。连接失败会区分地址不通、认证失败、接口异常与超时，沿用 FlowMedia 既有提示。

## 监控与能力差异

统一展示实际收到的版本、状态、分组、节点与订阅信息。Clash 还展示规则数量、活动连接、流量总量和速率；速率曲线仅由实际采样组成。接口没有提供的区域不显示。长列表有数量与截断标识，控制动作会再次向服务校验成员身份。

| 能力 | Clash / Mihomo | v2rayA |
| --- | --- | --- |
| 认证 | Bearer secret | 登录令牌，或用户名密码换取令牌 |
| 节点、状态 | `/version`、`/configs`、`/proxies` | `/api/version`、`/api/touch`、`/api/outbounds` |
| 连接列表 | `/connections` | 不将 `/api/connection` 误当连接列表 |
| 流量 | `/traffic`、`/connections` | 已核实的 2.5.10+ `/api/message` traffic 事件；收不到便不显示 |
| 探测 | 节点 HTTP URL 延迟 | 2.5.10+ TCP 节点探测，不等于目标网站可用性 |
| 切换 | Selector 现有成员 | 2.5.10+ 固定选择已有出站组成员 |
| 域名探测规则 | 支持指定 URL、分组与策略 | 不支持，不显示配置入口 |

**v2rayA 2.2.7.5：支持监控，禁用探测与切换。** 官方旧版探测会临时修改透明代理或重启核心，本插件不调用这些接口。无流量事件时不会显示零值占位。多成员分组没有返回明确选择时，不推断当前节点，也不自动切换。

## 策略

默认模式 `monitor` 只记录探测结果。`failover` 在当前节点达到失败阈值时选择健康节点；`optimize` 按间隔探测，并在达到延迟改善门槛后选择更快节点。手动选择和自动选择均需插件已启用。

配置字段对照：

| 字段 | 含义 / 默认值 |
| --- | --- |
| `group` | 需要监控/切换的分组；自动切换需要服务返回明确的当前成员 |
| `probe_url` | Clash 节点测试 URL，默认 `https://www.gstatic.com/generate_204` |
| `probe_timeout` / `probe_concurrency` | 3 秒 / 3 并发 |
| `failure_threshold` / `failure_window` | 2 次连续失败 / 300 秒窗口 |
| `optimize_interval` | 优选探测间隔 300 秒 |
| `cooldown` / `min_dwell` | 切换冷却 / 当前节点最短驻留，各 300 秒 |
| `min_improvement` | 延迟至少改善 50 ms |
| `excluded_nodes` | 排除关键词，逗号分隔 |
| `domain_rules` | 界面编辑的最多 8 条规则，包含名称、URL、分组、模式、排除关键词及启用状态 |

认证失败、接口格式异常、缺失的探测结果均不能作为节点故障证据。冷却按分组共享，防止多条规则相互切换。域名规则测试指定 URL 经节点访问的可用性，不会新增或改写代理核心路由规则。

调度每 30 秒触发，启用和手动执行也会触发。监控页面打开时每 5 秒刷新，隐藏页面暂停刷新；读取与连接测试不会执行切换。策略保存最近 120 组真实探测样本、40 条节点结果和 30 条事件；可用率是这些样本的成功比例，不表示全天在线率。暂不提供外部日报通知。

## 隔离和存储

插件依旧运行在无网络的隔离容器。网络读取和已声明的控制动作由主程序的固定适配器执行，不开放任意 HTTP 请求、任意代码界面或外部依赖。SDK 2 密码字段不会传入插件进程。请求期限、并发、响应体和快照均设上限；不跟随重定向，不输出原始接口异常和凭据。

插件通过 `get_service_snapshot()` 读取主程序快照，用 `get_data/save_data` 保存状态和摘要，使用现有 `notify` 模板记录状态变化。策略状态由主程序按插件 ID 单独保存。停用取消任务并保留数据；升级默认停用，需要再次启用。
